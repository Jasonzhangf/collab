# Collab v1 function map

| feature_id | owner | entry symbols | required gate |
|---|---|---|---|
| identity.peer-register | `identity` + `server` | `load_or_create`, `provision`, `handle_register` | every registration is peer; no first-worker promotion; parent provisions a child App Server thread identity before the agent starts |
| identity.master-authority | `server` + `subagent` | `handle_master_promote`, `handle_master_delegate`, `handle_master_status`, `live_master_id`, `replay` | no live master: approved self-promote with a live App Server thread; live master: only that master delegates to a live App Server peer; init/register never assign master; a dead recorded thread is not a live master; journal `RootAssigned` replays and rewrites as `MasterAssigned`; independent peers may decline a master invite; managed subagents must obey; live master may inspect and snapshot any managed subagent in the project |
| task.scheduler-assignment | live master scheduler | `handle_scheduler_dispatch`, `scheduler_dispatch_deduplicated`, `scheduler_assignment_events` | stable request ID; ordinary live idle registered peer before idle managed child; `Sent` + `TaskCreated(assigned)` + managed binding + pending audit are one journal transaction; audit success/failure is durable and retries preserve the same outcome; legacy `TaskDispatch` remains fail-closed |
| task.self-lifecycle | assigned task owner peer | `handle_task_accept`, `handle_task_register`, `handle_task_update`, `handle_task_deliver`, `handle_task_review`, `handle_task_integrated`, `handle_task_close` | owner authenticates and accepts an assigned task through `collab task accept`, atomically recording `assigned→working`; owner records candidate delivery; owner or live master records review and exact `refs/heads/main` integration; current lifecycle records cannot bypass gates through direct status, while legacy persisted `accepted` records without lifecycle evidence retain only owner-local `accepted→merged` compatibility; lifecycle evidence is journaled and replayable |
| resource.p2p-conflict | `server` | `task_conflicts`, `handle_task_wait`, close release projection | task operations return synchronously; exact subscribed release exits waiting and clears edge |
| wait.liveness | `server` | `handle_task_wait`, `wait_cycle`, `timers::tick` | bounded acyclic wait, responsible blocker owner, deadline state transition without unsolicited message |
| notification.subscription | `server::state` + `server` | `default_direct_message_events`, `registered_peer_default_events`, `restore_registered_peer_default_leases`, `handle_notification_subscribe`, `matching_subscription`, `handle_notification_unsubscribe` | peer registration owns one deterministic finite default direct-message lease; short explicit leases cannot suppress it; daemon replay restores it only for a matching registered App Server thread; resource/deadline/async-result remain one-shot |
| notification.appserver-wake | `server` + `timers` + `keepalive` | `abbreviated_subject`, `notification_text`, `attempt_notification_with`, `immediate_notify`, `queue_wakeup` | registered-only recipient; sending decoupled from the sender's terminal; required subject plus safe original-body preview and execute-not-ACK/wait action suffix; explicit messages use App Server `turn/start`, daemon wakeups/long-horizon notices use `thread/queue/add`; direct messages serialize through cooldown; dead/unowned thread or registered identity mismatch cancels subscription without storm; working agents defer background wakeups without burning attempts until working->idle transition; unacked notifications throttled after limit (default 3, configurable 1..=5) awaiting ACK to prevent terminal pollution and backlog; batch capped at 3 with inbox reminder; worker status query (`collab worker status`, `collab who`) inspects liveness, identity, agent state, unacked pressure, and snapshot diagnostic action; bulk ack via `collab ack --all`; worker freed (working->idle with empty tasks) emits event trigger to live master to drive worker saturation; unacked/absent worker emits diagnostic alert to live master with snapshot guidance |
| notification.context | `server` | `handle_context`, inbox/status handlers | authenticated read-only projection; durable body fetched through CLI/MCP |
| daemon.thread-route-resolution | `identity` + `server::ProjectRuntimeManager` + CLI | `identities_for_native_thread`, `resolve_route_by_native_thread`, `client::resolve_route`, `scope::route_for_native_thread`, `collab route resolve` | one context-free native-thread lookup selects the global identity's current typed runtime binding; historical route bindings are not candidates; `context`, `master status`, and thread-backed `Scope::resolve` consume the daemon result; zero/multiple/invalid matches fail explicitly; the lookup is read-only |
| daemon.project-scope | `scope` + CLI init | `project_root_for_init`, `lifecycle_project_root`, `init`, thread-aware `Scope::resolve`, `ensure_project_collab_mcp`, `ensure_codex_collab_permissions` | `collab init` and daemon lifecycle/config commands resolve the exact process cwd without consulting a terminal session; normal thread-backed commands resolve their project route through the daemon; MCP cannot select either; init merges shared `collab-mcp` and writes Codex/Claude project permissions |
| migration.peer-v1 | `server` | migration inspect/plan/apply/verify handlers, `replay` | legacy role fields are discarded; snapshot/replay preserves lifecycle |
| daemon.operator | CLI + `server::run` | `collab down`, `collab up`, `replay`, `daemon.lock` | explicit operator path, one socket writer, exclusive `daemon.lock` flock prevents duplicate daemon processes and unlinking of active daemon sockets, no role-derived authority |

Legacy `TaskDispatch`, transfer-master, master recovery, and automatic
idle-worker offers remain fail-closed. Live-master scheduler assignment is
owned by `task.scheduler-assignment`; explicit user-approved master promotion
and live-master delegation remain owned by `identity.master-authority`.
Codex root is not Collab master.
