# Collab v1 resource map

| resource_id | unique owner | truth store | allowed operations | forbidden relation |
|---|---|---|---|---|
| peer-identity | `identity::load_or_create` + Server registration | journaled `WorkerRec` | bind one App Server thread identity to its current runtime endpoint | inferred master from first register, copied token, claiming master from init/register |
| project-master-authority | live registered master peer through Server | journaled `Event::MasterAssigned` plus live App Server check | user-approved self-promote when no live master; live-master delegate to a live App Server peer | implicit first-register promotion, promote while a live master exists, claim from a dead thread, treating Codex root as Collab master |
| task-assignment | live master scheduler | journaled `SchedulerAdmissionRecord` plus `Sent`/`TaskRec` events | choose live idle registered peer before idle managed child; bind direct-message lease; persist one idempotent assignment by request ID | legacy `TaskDispatch`, automatic offer, duplicate reservation |
| task-lifecycle | assigned task owner peer | journaled `TaskRec` | accept assigned scheduler task, update, verify, integrate, close own task | another peer mutating lifecycle, accepting managed assignment through ordinary task entry |
| resource-claim | task owner peer through Server | active task feature/worktree claim | claim, hold, wait, release; conflict emits durable p2p notice | silent takeover, automatic release, global arbiter |
| wait-edge | waiter peer + blocking resource owner | `TaskRec.wait` | bounded wait, synchronous conflict result, deadline transition, subscribed release event | cycle, missing responsible peer/deadline/resume path |
| collaboration-journal | `server::Server` | `.agent-collab/server/journal.jsonl` | append/replay worker, task, message, migration events | manual JSON edits, silent replay skip |
| durable-mailbox | `server::Server` | `.agent-collab/mailbox/*.json` | persist required subject, original peer message, and subscribed event results | notification preview as truth, clearing during migration |
| notification-subscription | registered peer through Server | journaled `NotificationSubscription` + control-only wake binding | registration creates/refreshed deterministic seven-day default direct-message lease; daemon replay restores it only for a still-matching registered App Server thread; query methods; register exact event/subject/TTL; status; unsubscribe; consume one-shot event subscriptions | unregistered or stale thread subscription, short explicit lease suppressing the default, payload-derived state, unbounded lease, another peer mutation |
| appserver-wake | `server` + `Event::WakeAttempted` | journaled attempt ledger + transient id/subject/body preview | only active subscription; required abbreviated subject; safe one-line original body preview; explicit action suffix directs the Agent to read durable detail and execute selected in-scope work instead of ACK/wait; absent/unknown fail closed; dead/unowned App Server thread or registered identity mismatch transitions subscription to unavailable; working agents defer background wakeups until working->idle transition without burning attempts; unacked notifications paused after limit (default 3, configurable 1..=5) awaiting ACK to avoid backlog pollution; batch capped at 3 with inbox indicator; lifetime max three per message; direct-message cooldown serializes delivery; explicit messages use App Server `turn/start`, while daemon wakeups/long-horizon notices use `thread/queue/add` | missing subject, terminal control injection, notification burst, wake while working, automatic continuation, shell input, normal progress report |
| agent-context | `server::handle_context` | read-only Server state projection | peer identity, own tasks/waits, inbox, next actions | consuming notification, board management, other-peer supervision |
| thread-route-resolution | `identity` + `server::ProjectRuntimeManager` | global identity current runtime binding plus the matching typed project `runtime_binding`; `routes.jsonl` is admission/storage only | read-only native-thread lookup through context-free `RouteResolve`; return exactly one `RouteResolution`; historical routes are excluded; zero matches `ROUTE_RESOLVE_NOT_FOUND`; multiple current identities or matching current routes return `ROUTE_RESOLVE_AMBIGUOUS` | cwd, Git worktree, tmux, historical route, or `routes.jsonl` selecting a route; token leakage; mutation during resolution |
| project-control-root | `scope::project_root_for_init` + `scope::lifecycle_project_root` + thread-aware `Scope::resolve` | `collab init`/lifecycle: exact process cwd; thread-backed commands: daemon route resolution | initialize/control only the cwd project; resolve normal commands from `CODEX_THREAD_ID` when present | Agent/MCP path selection, Git or ancestor inference, sibling sharing, invalid path; an uninitialized terminal cannot block init; lifecycle commands must not follow a foreign thread binding |
| daemon-maintenance | explicit local operator command | project socket/PID/events | install, controlled down/up, replay verification | deriving authority from peer role or mailbox text |
| migration-transaction | initiating authenticated peer + Server freeze | journaled `MigrationRecord` | inspect, plan, freeze, snapshot, restart, rebind, verify, resume | permanent master requirement, second writer, invented owner |

`/goal` delegation and interactive task recognition are outside this v1 milestone.
